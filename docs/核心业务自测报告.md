## 二、发现清单与修复状态

### 🔴 A 级：真业务缺陷（已全部修复 ✅）

#### A1.【中高 → 已修复】爬虫空结果/少结果时不再把整个日期范围标记为"已完成"

- **位置**：`core/data_collector.py` `_run_one`、`core/base_crawler.py` `crawl_incremental`
- **原缺陷**：增量模式下，`fetch_by_date` 无论返回 0 条还是远少于待抓日期数，`pending` 里的**全部日期**都会被 `mark_dates_completed` 标记，此后这些日期永远不再被抓取（除非手工删除 `crawl_history.json`）。叠加各爬虫只抓列表第一页并截断（`ndrc.py:53`、`nea.py:53`、`china5e.py:53` 均为 `filtered[:self._max_items]`，`miit.py:59` 取 `all_entries[:max_items*3]`），15 天窗口内较旧新闻漏抓后**永久不可恢复**。
- **修复方式**：新增 `base_crawler.resolve_dates_to_mark()`，按返回条目的 `publish_time` 反推实际覆盖日期：
  - 空结果 → **不标记任何日期**，保留重试机会；
  - 少结果 → **只标记实际有数据的日期**，未覆盖日期下次重试；
  - 有数据但日期全部无法反推 → 回退标记全部 pending（防无限重试）。
  - `data_collector.py` 与 `base_crawler.crawl_incremental` 均改用该逻辑。
- **回归证据**：
  - `修复: 空结果不再标记任何日期` → completed=[]（原为 7 天全标）✅
  - `修复: 少结果只标记有数据日期` → 只标记返回新闻对应日期 ✅
  - `修复: 日期无法反推时回退标记全部` → 7 天全标（防无限重试）✅

#### A2.【中 → 已修复】AI Prompt 声称的条数与模型实际可见条数一致

- **位置**：`core/ai_analyzer.py` `build_crawl_user_prompt`、`core/analyzer.py`、`workers/ai_analysis_worker.py`
- **原缺陷**：Prompt 写 `共提供 {len(items)} 条`，但 `build_news_context` 只取前 `max_items=30` 条（输入可到 200 条），模型统计口径被误导；`ai_analysis_worker.py` 把 15/30 天数据也标注为"最近 7 天"。
- **修复方式**：
  - `build_crawl_user_prompt` 新增 `max_items` 参数，声称条数改为 `min(len(items), max_items)`，与实际上下文严格一致；
  - `TimeRange` 扩展为 `24h/3d/7d/15d/30d`，新增 `analyzer.days_to_time_range()`：1→24h、≤3→3d、≤7→7d、≤15→15d、>15→30d；
  - `RecentNewsAnalysisWorker` 与 `AiAnalysisWorker` 的 time_range 白名单与 days_map 同步扩展。
- **回归证据**：
  - `修复: Prompt 声称条数=30(截断一致)`、`修复: 声称条数与上下文一致` ✅
  - `修复: max_items=50 声称50条` ✅
  - `天数映射: 15→15d`、`30→30d`、`45→30d`、`标签: 15d=最近15天` ✅

#### A3.【中 → 已修复】多边分析页"日期范围"按绝对日期过滤

- **位置**：`main_window.py` `_sync_manual_date_range`、`refresh_news_async`、`_on_news_days_changed`；`workers/ai_analysis_worker.py` `NewsLoadWorker`；`core/database.py`
- **原缺陷**：用户选择起止日期后，控件换算成 `days` 走 `list_recent_news(days)` 滚动查询（从今天往回数），历史窗口（如 8-01~8-10）显示的是"最近 N 天"，与按绝对日期删除的功能（`_delete_news_by_date_range_async`）口径不一致。
- **修复方式**：
  - `database.py` 新增 `list_news_by_date_range()`（绝对区间查询，含两端当天）；
  - `NewsLoadWorker` 新增 `start_date/end_date` 参数，二者齐备时走绝对日期查询；
  - `refresh_news_async` 以日期选择器为权威，读取绝对区间传给 worker；
  - 新增 `_on_news_days_changed`：「最近 N 天」spinbox 变化时同步日期选择器为 (今天-(N-1) ~ 今天)，再按绝对日期刷新；日期选择器变化时反向同步 spinbox（`_sync_manual_date_range` 保留），两控件不再互相打架；
  - 初始/重置窗口从 `-7` 调整为 `-6`（与 spinbox=7 的 7 天窗口一致）。
- **回归证据**：
  - `修复: 历史窗口内旧新闻被展示`、`修复: 窗口外新新闻被排除`、`修复: 单日窗口含当天` ✅
  - UI 冒烟：日期选择器→spinbox 同步=10、spinbox→日期选择器 15 天窗口、历史窗口 8-01~8-10→days=10 ✅

### 🟡 B 级：建议改进（已全部修复 ✅）

#### B1.【低中 → 已修复】`parse_analysis_json` 围栏容错

- **位置**：`core/analyzer.py`
- **原缺陷**：正则 `^```(?:json)?...```$` 要求全文恰好是围栏，模型输出带前后说明文字即 `json.loads` 抛错。
- **修复方式**：逐级降级——① 全文围栏剥除后解析；② 从每个 `{` 处 `JSONDecoder.raw_decode` 尝试，命中即返回；③ 仍失败才抛原始 `JSONDecodeError`。
- **回归证据**：`修复: JSON 前有说明文字可解析`、`修复: JSON 围栏后有文字可解析`、`修复: 说明文字含{也能解析` ✅；非法 JSON 仍正确抛异常 ✅。

#### B2.【低 → 已修复】邮件 HTML 转义

- **位置**：`main_window.py` `_send_ai_result_email_async`、`_send_scheduled_report_email_async`
- **原缺陷**：f-string 拼接 AI 生成的 `title/summary/analysis/impact` 进 HTML 模板，未转义，模型输出含 `<`/`&` 会破坏渲染甚至注入 HTML。
- **修复方式**：改用 `from html import escape`，两个函数的所有动态字段统一转义（注意：不能 `import html` 后用 `html.escape`——函数内局部变量 `html`（模板字符串）会遮蔽模块名导致 `UnboundLocalError`，冒烟测试当场捕获并修正）。
- **回归证据**（UI 冒烟，EmailSendWorker 打桩不真发）：`<script>`、`<b>加粗`、`&`、`<img`、引号均被转义；定时报告 `<报告>`、`A&B` 同样转义 ✅。
